# Technical Case Study: Endpoint Security Integration & Legacy Target Telemetry (Metasploitable 2)

## 1. Executive Summary
This report documents the successful integration of a legacy 32-bit vulnerable target machine (**Metasploitable 2**) into a centralized **Wazuh SIEM** architecture. Due to cryptographic and architecture constraints inherent in legacy operating systems released in 2008, standard automated deployment methods fail. This lab details the workaround methodology utilized to achieve telemetry synchronization, including local package deployment, secure out-of-band file transfer via SCP over TCP Port 22, and manual service initialization.

## 2. Network Topology & Lab Environment
* **Wazuh Manager IP:** `192.168.239.128`
* **Metasploitable 2 Target IP:** `192.168.239.129`
* **Network Mode:** VMware Workstation NAT mode with local virtual network routing and DHCP gateway services.
* **Architecture:** 
  * Manager: Modern 64-bit Linux distribution running Wazuh SIEM server.
  * Target: Legacy 32-bit (`i386`) Ubuntu 8.04 (`hardy`) system running Metasploitable 2.

## 3. Challenges Encountered & Technical Analysis

### A. Architecture Incompatibility
Standard automated installation scripts generated by modern SIEM dashboards assume 64-bit (`amd64`) modern Linux distributions. Direct execution fails on Metasploitable 2 because the target operates on a legacy 32-bit (`i386`) architecture, requiring a specific matching legacy agent build (`v4.3.10`).

### B. Cryptographic Handshake Failures
Attempting to fetch packages directly from the internet inside the target VM resulted in terminal errors:
* **Error Encountered:** `OpenSSL: error:14077410:SSL routines:SSL23_GET_SERVER_HELLO:sslv3 alert handshake failure`
* **Root Cause:** Metasploitable 2 utilizes an obsolete OpenSSL library that only supports weak or deprecated encryption protocols (such as SSLv3/TLS 1.0). Modern Content Delivery Networks (CDNs) hosting repository packages reject these outdated cryptographic handshakes outright to prevent downgrade attacks.

## 4. Step-by-Step Implementation

### Step 1: Out-of-Band Browser Download
To bypass the vintage operating system's cryptographic limitations, the package was downloaded directly on the modern Windows host machine using a standard web browser over secure TLS 1.3.
* **Target URL:** `https://packages.wazuh.com/4.x/apt/pool/main/w/wazuh-agent/wazuh-agent_4.3.10-1_i386.deb`

### Step 2: Secure Copy (SCP) File Transfer via TCP Port 22
With the file available locally on the Windows host, the package was securely transferred across the network to the target VM's home directory.
* **Protocol & Port:** Secure Shell (SSH) / Secure Copy Protocol (SCP) operating over **TCP Port 22**.
* **PowerShell Command Executed:**
  ```powershell
  scp -o HostKeyAlgorithms=+ssh-rsa -o PubkeyAcceptedKeyTypes=+ssh-rsa wazuh-agent_4.3.10-1_i386.deb msfadmin@192.168.239.129:~
  
### Step 3: Local Package Installation and Manager Registration
After confirming the file's presence on the target machine, the package manager installed the agent binary while binding it to the local Wazuh manager IP (192.168.239.128).
Command Executed:
sudo WAZUH_MANAGER="192.168.239.128" dpkg -i wazuh-agent_4.3.10-1_i386.deb

### Step 4: Service Initialization
Because Metasploitable 2 utilizes a legacy initialization structure rather than modern system service wrappers, the agent sub-daemons were explicitly started using the initialization script directory.
Command Executed:
sudo /etc/init.d/wazuh-agent start

### Step 5: Automating Service Persistence on Boot
To ensure operational resilience across system reboots without requiring manual terminal intervention, the agent initialization sequence was made persistent by modifying the system startup configuration.
Configuration Modified: `/etc/rc.local`
Command Appended: `/etc/init.d/wazuh-agent start` (inserted prior to `exit 0`)

### Step 6: Dashboard Verification and Telemetry Sync
Once the initialization script launched all local agent sub-daemons, the Metasploitable 2 target established an authenticated channel back to the Wazuh manager. Logging into the centralized Wazuh web UI confirmed successful node registration.
Dashboard Status: The agent appeared as Active (1) under agent ID 001, named metasploitable, running Ubuntu 8.04 with version v4.3.10.

## 5. Troubleshooting & Challenges**
Legacy OpenSSL Blocks: Outdated crypto libraries required manually pulling packages through the host environment rather than direct repository downloads.
Initialization Frameworks: Bypassed missing modern systemd wrappers by invoking legacy SysV-init scripts directly via /etc/init.d/.

## 6. Security Purpose & Operational Relevance
In a professional Security Operations Center environment, integrating legacy infrastructure or unmanaged endpoints into a unified SIEM is vital for maintaining visibility over end-of-life systems that are frequently targeted by attackers.

## 7. Lessons Learned
Out-of-band file staging via SCP is a reliable workaround when legacy hosts face modern TLS/SSL repository rejections.
Verifying architecture compatibility (i386 vs amd64) prevents silent failures during package deployment.
